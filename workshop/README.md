# 麻雀ラボ：開発者向けセキュリティ演習

mainブランチの麻雀ゲーム本体を使う、架空データだけの演習版です。猫と牌の画面、30秒タイマー、出題・採点、清一色への切替、終了後の振り返りは元の実装をそのまま再利用しています。通常版のファイル、接続設定、DBスキーマは変更していません。

## まずローカルで動かす

Node.js 24以上で、リポジトリのルートから実行します。依存のインストールやビルドは不要です。

```sh
node workshop/server.js
```

`http://127.0.0.1:4176` を開き、ターミナルに表示されるペア1またはペア2の参加コードで入室してください。`localhost` ではなく、表示されたURLを使用します。参加コードは `neko-`・`tile-` などの語とランダム5文字を組み合わせた10文字です。ローカル版は初回起動時に生成してSQLiteへ保存、Supabase版はSecretsへ設定したコードを継続利用します。別ペアの確認には別のブラウザプロファイルを使います。サーバーはループバックアドレスだけで待ち受けます。

- SQLiteの実SQLを使います。SQLiを文字列比較で模擬しているものではありません。
- ペアごとに別のメモリ内DBを作り、検索接続は読み取り専用です。
- ユーザー・成績・進捗は `workshop/game.sqlite` に保存します。ログアウト・サーバー再起動後もランキングに記録が残ります。DBファイルはGit管理対象外です。
- 「このモードをリセット」は自分の現在のモードだけを初期化します。
- 弱点版・修正版の名前と進捗は独立しています。比較時は同じ入力をもう一度保存してください。
- 演習はHTTP APIが必要です。通常版の `index.html` の `file://` 動作はそのままですが、演習版は `file://` では動きません。

## 元ゲームとの接続

- 入室すると元の「麻雀 待ち当て」開始画面が開きます。「はじめる」で30秒ゲームを遊べます。
- 終了時の実際の得点・正解数・回答数・最高連続を演習APIに保存し、マイページの統計と最近のプレイ、上位10件ランキングへ反映します。
- 元のマイページに非公開メモ、表示名の安全なプレビュー、登録者検索を追加しています。開始画面から開けるので麻雀を解かずに演習できます。
- ランキングの保存名は、localStorageを読み取れる同一オリジンのiframeで描画しています。終了画面のランキングと、開始画面から開くランキングは同じデータ・描画領域を使います。
- ゲーム中はモード変更・リセット・退室を無効化します。課題を開いてもゲームの時計は止まりません。
- `main.js`、`mahjong-logic.js`、`tile-art.js`、`ranking.js`、`style.css` はルートの元ファイルと同一です。`index.html` は元HTMLに演習用の差分を加えています。通常版の `online.js` と `account.js` を読み込まず、`app.js` の演習用アダプターで接続します。
- 元ゲームを更新した際は `node workshop/sync-game.js` で同期できます。生成済みファイルを含むため、通常の起動・配信にビルド工程は不要です。
- 得点は元ゲームと同様にクライアントで計算し、APIは範囲を検証します。得点改ざん耐性を追加したものではなく、今回の課題対象外です。

## 3問の内容

問題文・3段階のヒント・原因と修正は画面内にあります。表示は易しいと想定する順にSQLi→XSS→IDORです。検索欄だけで試せる課題から、保存・描画の経路を追う課題、通信を変更・再送する課題へ進みます。難易度は事前試行で調整します。

| 問題 | 到達目標 | 意図的な弱点 | 修正版 |
| --- | --- | --- | --- |
| 非掲載の登録名 | SQLで非掲載の架空登録者を取得して証拠コードを提出 | 検索語をSQLに連結 | パラメータ化 |
| ランキングを書き換える | 保存した名前を経由してJSを実行し、DOMバナーを追加 | 名前をランキングでinnerHTMLに渡す | textContentで文字として表示 |
| 他人のマイページ | ライバルの非公開メモの合言葉を提出 | 同一領域内のプロフィール所有者チェック欠落 | 本人の101以外を404にする |

ランキングのニックネームと非掲載の登録名は別データです。「すでに公開されている名前を取得して成功」という問題にはしていません。

## 講師向けの解答例

具体的なDevToolsの操作、証拠提出、修正版との比較は [講師用の模範解答](ANSWERS.md) にまとめています。

1. 検索欄へ `' OR 1=1 -- `（末尾に空白）を入力。非掲載名とレスポンスの `NAME-...` を確認して提出。
2. 名前を `<img src=x onerror="celebrate()">` にして保存。プレビューは文字のままであることを確認し、ランキングを開く。sandbox内で画像読み込みが拒否されるとonerrorが実行され、教材関数がDOMを追加し成功通知を送る。
3. マイページを開き、Networkの `GET /api/vulnerable/profiles/101` を102へ変更して再送。`memo` の `NOTE-...` を提出。

XSSの成功通知はブラウザからのイベント報告です。iframeの送信元・一回限りのチケット・リセット世代を確認しますが、DevToolsを使う本人によるAPIの直接呼び出しまで防ぐ採点システムではありません。講師は保存→取得→実行という経路も確認してください。単なるHTML挿入とJavaScript実行は説明で区別します。

修正版では、IDORは404、SQLiは非掲載名なし、XSSは入力文字がそのまま表示されます。正常なプロフィール取得・登録者名の検索・普通の名前表示は維持します。

登録者検索は同じ参加コードで登録したユーザーの現在の公開表示名を対象とし、ログアウト後も検索できます。通常の検索に架空のゲストは含めません。結果は最大50件で、長い名前は折り返し、一覧はスクロール枠に収めます。SQLi演習用の非掲載名は架空データだけを検索用領域に追加し、他の実参加者の非公開名やプロフィール本文は検索接続に渡しません。

## Supabaseで使用する場合

接続先は `project.json` の演習専用プロジェクト `xroxdmybbpxulqgezvnh` です。通常版のプロジェクトへの設定は準備スクリプトとローカルサーバーで拒否します。

この環境では2ペア分の `setup.sql`・`secrets.env`・`participants.txt` を `.setup/xroxdmybbpxulqgezvnh/` に生成済みです。Git対象外・アクセス権限定のファイルで、公開ディレクトリには置いていません。SQL適用・Secrets登録・Edge Functionのデプロイは完了し、実API経由の認証・DB操作・課題・領域分離を確認済みです。

Supabase CLI 2.121.0を一時キャッシュへ取得済みです。初回の認証はターミナルで行います（トークンをチャットに貼らないでください）。

```sh
npm exec --cache /private/tmp/mahjong-supabase-npm --yes --package supabase@2.121.0 -- supabase login
```

接続確認・適用後、ローカル画面からSupabaseへアクセスする起動方法です。通常起動のSQLiteとはセッションを分け、接続失敗時にSQLiteへフォールバックしません。

```sh
node workshop/server.js --supabase
```

フロントは `http://127.0.0.1:4173`、APIは専用Edge Functionになります。ローカルの参加コードではなく、生成済み `participants.txt` のコードを使用します。

実装は `supabase/functions/workshop/index.ts` にあります。APIの業務処理はローカル版と `_shared/core.js` を共有し、DBアクセスだけが異なります。Edge Functionは固定版の `postgres@3.4.5` を使用します。通常版へnpm依存は追加しません。

**以下は新規環境を準備する場合の手順です。現在の専用プロジェクトには適用済みなので、同じ初期SQLを再実行しないでください。**

1. 通常版と異なる、教材専用の新規Supabaseプロジェクトを準備します。既存プロジェクトへ適用しないでください。
2. 次のコマンドで必要なペア数の準備ファイルをローカル生成します。出力先は新規ディレクトリを指定します。

   ```sh
   node workshop/prepare-supabase.js 2 /private/tmp/mahjong-workshop-setup
   ```

3. 生成された `setup.sql` を教材専用DBへ適用します。SQLは一度だけ実行する初期作成用で、既存ロール・スキーマを破壊して再作成しません。シードは架空の3名のみです。
4. `secrets.env` の接続先を教材プロジェクトへ置換します。Direct connection形式で生成されます。poolerを使用する場合はダッシュボードで確認した接続先・ポートへ変更し、ユーザー名は `lab_1_reader.<project-ref>` のように専用ロールを維持します。`postgres`やservice_roleへ置き換えないでください。
5. `WORKSHOP_ORIGIN` に教材フロントのHTTPSオリジン（ローカル確認では `http://127.0.0.1:4173`）を設定します。末尾のスラッシュやパスは付けません。`WORKSHOP_SESSION_SECRET` と `WORKSHOP_LABS` はサーバー側Secretsにだけ保存します。
6. `workshop/` をSupabase CLIの作業ディレクトリとして、教材プロジェクトにSecretsと `workshop` 関数を設定します。`supabase/config.toml` の `verify_jwt = false` は独自HMACセッションを関数内で検証するためです。Supabase Authのログインとして参加コードを扱っているわけではありません。
7. フロントの `public/config.js` には `https://<教材project-ref>.supabase.co/functions/v1/workshop` の公開URLだけを設定します。
8. **`workshop/public/` だけを**通常版とは別のオリジンへ配信します。リポジトリ全体や `workshop/` 全体を配信しないでください。生成したSQL・Secrets・参加コード一覧は配信もコミットもしません。
9. `participants.txt` からペアごとのコードを配布します。共有有効期間はセッション8時間です。終了時は関数を停止するかSecretsをローテーションし、保存データを所定の期間後に破棄します。

### Supabase側の分離

- ペアごとに専用スキーマ、readerログイン、writerログインを作ります。ロールは管理権限・他ロールのメンバーシップ・BYPASSRLSを持ちません。
- readerは自分の `directory` のSELECTだけ、writerは自分の `state` のSELECT/INSERT/UPDATEだけを持ちます。所有者はいずれの接続ロールとも異なります。
- SQLiはreader接続の読み取り専用トランザクションだけで実行します。writerはパラメータ化した固定クエリだけです。
- 検索語以外のスキーマ名・接続資格情報は、検証済みセッションに対応するサーバー設定から決めます。bodyの領域指定は使用しません。
- ペア別の接続プールを使います。管理者ログインから `SET ROLE` する構成ではありません。
- SQLiクエリにも固定のバインド引数を置き、複文を受け付けないextended query経路を使います。これは意図したWHERE条件のSQLiを防ぐものではありません。
- 進捗・秘密メモ・XSSチケットはreaderが読めない `state` に保存します。DB行ロックで同じモードの更新とリセットを直列化します。
- ペアの状態を別テーブル権限で守る設計であり、任意SQLから変更可能な `lab_id` セッション変数やWHERE句に境界を依存させません。
- DBシステムカタログの一部やDB資源自体は共有されます。これは物理分離ではなく、負荷攻撃を防ぎきる環境ではありません。強い分離が必要ならペア別プロジェクトを使用します。
- 教材スキーマをData APIの公開スキーマに追加しません。既存の権限追加・SECURITY DEFINER関数を持ち込まず、新規の教材プロジェクトで検証します。

### クラウドの転送形式と実通信テスト

Supabaseの入口にあるCloudflareが生の教材用SQLi文字列をGET・POSTともに403で遮断したため、ブラウザはPOST本文を `{encoding:"base64-json",data:"…"}` として転送します。APIでUTF-8のJSONへ復号してから処理します。これは暗号化・認可・SQLi対策ではありません。修正版のパラメータ化とDB権限が実際の防御です。「演習課題」に復号方法を表示しています。IDORの取得URLは通常のGETのままです。

PostgreSQLのJSONBには `sql.json()` でオブジェクトを保存します。事前に `JSON.stringify()` した文字列をJSONBへ渡すと二重エンコードになることを実DBで確認して修正しました。

```sh
node workshop/check-remote.js --connection-only
```

検証用参加者を新規登録して接続を確認します。`--connection-only` を省略すると課題・参加者分離を検証し、作成した検証ユーザーだけをリセットします。既存参加者の状態は変更しません。検証用の登録データはDBに残ります。資格情報は出力しません。

### 静的配信時のヘッダー

ローカルサーバーは設定済みです。Supabaseを使って別ホスティングに置く場合、フロントに次を設定し、connect-srcの接続先だけ教材APIへ変更してください。

```text
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; frame-src 'self'; connect-src 'self' https://<教材project-ref>.supabase.co; object-src 'none'; base-uri 'none'; frame-ancestors 'none'
Cache-Control: no-store
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
```

`ranking-frame.html` だけは次のCSPにします（HTML内にも同等のmeta CSPがあります）。親ページの厳しいscript-srcをこのファイルへ重複設定すると演習用イベント属性も止まります。

```text
Content-Security-Policy: default-src 'none'; script-src 'self' 'unsafe-inline'; style-src 'unsafe-inline'; img-src 'none'; connect-src 'none'; form-action 'none'; base-uri 'none'; frame-ancestors 'self'
```

iframeのsandboxは `allow-scripts allow-same-origin` です。localStorageの直接読み取り演習に対応するため、親画面と同じオリジンで実行します。この構成は親画面やsessionStorageへのアクセスを隔離しません。弱点版では他ユーザーを含むランキング名をHTMLとして描画し、閲覧者のブラウザーで実行します。修正版はすべて文字列として描画します。クリア通知は送信元iframe・オリジン・チケットを検証します。

## 40分の進行例

導入・正常操作7分、マイページ10分、SQLi10分、解説と修正比較10分、振り返り3分。XSSは早期終了者向けの追加問題にすると当初の40分枠に収まります。3問全員必須にする場合は、各問の時間を短縮するより開催枠を延長する方が原因と修正の説明時間を確保できます。


## 名前と参加コードでの新規参加

入口では参加者名（1〜40文字のニックネーム）と参加コードだけを入力します。ログインID・パスワードは不要です。同じ名前・コードでも、参加するたびに新しいユーザーIDを発行します。過去ユーザーへの再ログインはありません。同じタブの再読み込みでは現在のセッションを維持します。

ログアウトするとサーバー側のセッションと端末のトークンを無効にして参加画面へ戻ります。期限切れ・通信エラーでも端末側はログアウトできます。通信エラー時はサーバー側の失効を確認できない旨を表示します。プレイ中のログアウトでは、その進行中のプレイを中断し、次の参加者へ引き継ぎません。

## IDと成績・ランキングの永続化

- 数値ユーザーIDはDBで採番し、既存IDや削除済みIDを再利用しません。ローカルはSQLite AUTOINCREMENT、Supabaseはグループ共通シーケンスを使います。
- `/status` の `me` が本人IDです。演習の架空ライバルは本人ID+1であり、同じ番号の実参加者の非公開情報にはアクセスしません。
- 新規ユーザーの最高点・プレイ回数は0。全履歴から本人の成績を計算します。
- 同じ参加グループのユーザーごとの最高点を1件ずつ、上位10人までランキングに掲載します。同点は先の記録を優先します。ログアウト・新規参加後も以前のユーザーの記録はランキングに残ります。
- 弱点版・修正版はゲーム履歴を共有します。演習の名前・非公開メモ・成功状況だけがモード別です。演習リセットでもゲーム成績は消しません。
- 弱点版は他の実参加者のランキング名もHTMLとして扱います。修正版は文字として表示します。未掲載の本人には順位・成績に含まれない演習用プレビューを表示します。
- `node workshop/server.js` は `workshop/game.sqlite` に保存します。以前のログインID方式のSQLiteも、ユーザーID・成績・セッションを保持して、不要な認証情報の列を削除します。旧メモリ版サーバーのデータは自動移行しません。
- `createWorkshop()` も既定で永続DBを使います。テストだけ `{ memory: true }` を指定して隔離します。`npm run dev` で4176番の開発環境を起動でき、ソース変更時には自動再起動します。

## 公開版への反映

既存Supabaseには `supabase/migrations/202610190001_accounts_and_scores.sql` を適用後、Edge Functionとフロントを一緒に更新します。以前の移行（202610180002〜0004）が適用済みであることが前提です。旧サンプルを除き、両モードの実プレイをIDで重複排除して引き継ぎます。2026年10月20日に演習用公開環境へ適用済みです。移行前の17ユーザー・11件の実プレイ記録を保持し、公開APIで別ユーザー間のランキング共有・登録者検索・非公開設定・ログアウト後の記録保持を検証しました。検証用ユーザーと得点は削除済みです。この移行SQLは適用済み環境で再実行しないでください。

検証：ローカルのAPIと画面ロジックのテストで、名前とコードのみの参加、同時登録、重複しないID、DB移行、再起動後のランキング、演習リセットからの成績分離、通信失敗時のログアウトを確認しています。Supabase移行SQL・Edge Functionの実環境適用と、画面でのゲーム全操作・スマホ幅の確認は未実施です。
