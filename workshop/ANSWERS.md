# 講師用：3問の模範解答

対象は自分に割り当てられた演習領域のみです。麻雀をプレイする必要はありません。開始画面から「マイページ」「ランキング」「演習課題」を開けます。

準備：入室後、「演習課題」の比較モードを「弱点版」にします。Chromeの開発者ツールを開き、Network（ネットワーク）でFetch/XHRを表示します。課題画面は「ゲームへ戻る」で閉じられます。

## 01 非掲載の登録名：SQLインジェクション

1. 「弱点版」に戻し、マイページ下部の「登録者検索」を開きます。
2. まず `公開` と入力して検索します。「公開ゲスト猫」だけが返ることを確認します。Networkでは `POST …/vulnerable/directory` です。
3. 検索語を次に変えます。末尾の `--` の後ろには半角スペースを一つ入れます。

   ```text
   ' OR 1=1 -- 
   ```

4. 「検索」を押します。「架空登録者・青葉」「架空登録者・紅葉」を含む3名が返ります。
5. レスポンスの `evidence`、または画面の「証拠コード」に表示された `NAME-...` をコピーします。
6. 「演習課題」の01へ提出してクリア通知を確認します。登録名そのものではなく証拠コードを提出します。

引用符で検索文字列の外へ出て、`OR 1=1` で条件を成立させ、`-- ` で後続をコメント化しています。弱点版は検索語をSQLに連結するため、掲載条件も回避されます。DBの管理権限を得る課題ではなく、検索用ロールが読める自分の演習表の範囲で成立します。

修正比較：「修正版」に切り替え、同じ検索語を入力します。非掲載名は返りません。通常の `公開` 検索は引き続き1件返ります。修正版は検索語をSQLの構文として扱わず、バインドパラメータとして渡します。

### Networkの本文を読みたいとき

Supabaseの入口で教材文字列が遮断されるため、現在のPOST本文は次の転送形式です。検索欄へは上記の文字列をそのまま入力すればよく、参加者が手動でBase64化する必要はありません。

```json
{"encoding":"base64-json","data":"…"}
```

Request Payloadの `data` の値をコピーし、次の `コピーしたdataの値` を置き換えてConsoleで実行すると元のJSONを確認できます。

```js
JSON.parse(new TextDecoder().decode(
  Uint8Array.from(atob("コピーしたdataの値"), c => c.charCodeAt(0))
))
```

検索なら `{q: "…"}`、名前保存なら `{name: "…", generation: "…"}` が見えます。Base64は暗号化でもSQLi対策でもありません。レスポンスは通常のJSONです。

## 02 ランキングを書き換える：保存型DOM XSS

1. 「弱点版」のマイページを開きます。
2. 表示名へ次を入力します。

   ```html
   <img src=x onerror="celebrate()">
   ```

3. 「保存前のプレビュー」で、入力が文字として表示されることを確認します。この時点ではスクリプトは実行されません。
4. 表示名の「変更」を押します。Networkの `POST …/vulnerable/profile` で保存処理を確認できます。
5. マイページの「ランキングを見る」、または開始画面の「ランキング」を押します。
6. `GET …/vulnerable/ranking` のResponseに保存した名前が含まれることを確認します。
7. ランキング枠内に `🎉 XSSからDOMを追加できました！` のバナーが出て、自動で課題クリアになります。02はコード提出不要です。

ランキングだけが保存名を `innerHTML` へ渡しています。画像読み込みが失敗すると `onerror` が実行され、教材関数 `celebrate()` が `div#lab-confetti` をDOMへ追加します。単にHTMLタグが表示されたことと、JavaScriptが実行されたことを区別します。

Elementsでランキングのiframe内を確認すると、追加された `div#lab-confetti` を観察できます。実行範囲はsandbox付きiframeです。入力→保存→ランキングの取得→HTMLとして描画→イベント実行、という経路を追うのがこの問題のポイントです。

修正比較：「修正版」は別の保存状態なので、同じ名前をもう一度入力して「変更」し、ランキングを開きます。入力文字列がそのまま表示され、バナーは出ません。修正版は `textContent` を使います。

バナーが出ない場合は、比較モード、保存成功、ランキングの再取得、Responseに保存名が入っているかを順に確認してください。初期データには本人のランキング記録があり、麻雀を解かずに試せます。

## 03 他人のマイページ：IDOR

1. Networkを開いたまま、開始画面の「マイページ」を押します。すでに開いている場合は一度閉じて開き直します。
2. `profiles/{自分のUUID}` のGETリクエストを選びます。Responseで、自分の名前と練習メモが返っていることを確認します。
3. そのリクエストを右クリックし、Copy → Copy as fetch を選びます。
4. Consoleにコピーしたコードを置き、URL末尾の `/profiles/{自分のUUID}` だけを `/profiles/102` に変更して実行します。Authorizationヘッダーなど、他の値はそのまま使います。ログイン主体を変更する操作ではありません。
5. Networkへ戻り、新しく発生した `102` のResponseを確認します。弱点版ではHTTP 200で `name: "ライバル猫"` と本人限定メモが返ります。
6. `memo` の中から `NOTE-...` だけをコピーします。「本人限定の練習メモ：」は含めません。
7. 「演習課題」を開き、03の証拠コード欄へ貼り付けて「提出」。クリア通知を確認します。

Consoleは `http://127.0.0.1:4173` のゲームページで開いてください。Supabaseダッシュボードなど別ページのConsoleからは、許可オリジンが異なるため拒否されます。URL文字列にはMarkdownの `[URL](URL)` ではなく、生の `https://…` だけを入れます。コピーしたBearerトークンは自分の演習セッション用です。

期待される通信の差：

```text
GET …/workshop/vulnerable/profiles/{自分のUUID}  → 自分
GET …/workshop/vulnerable/profiles/102  → ライバル（本来は閲覧不可）
```

これは「取得するIDを変えたら、同じログイン状態で他人の情報が返った」という認可不備です。IDが連番であることだけが問題なのではありません。

修正比較：「修正版」に切り替え、マイページを開き直します。今度は `/fixed/profiles/{自分のUUID}` の通信をコピーし、末尾を102に変えて再送します。404で拒否され、自分のUUIDでは引き続き200です。古い `/vulnerable/` のリクエストを再送すると、画面のモードに関係なく弱点版へアクセスするため注意してください。

## 解説で押さえること

| 課題 | どこで信頼境界を越えたか | 修正の中心 |
| --- | --- | --- |
| IDOR | クライアントの対象IDを閲覧権限と取り違えた | サーバー側でログイン主体と所有者を照合 |
| SQLi | 入力データがSQL構文になった | パラメータ化。DBの最小権限も併用 |
| XSS | 保存済みの文字列を実行可能なHTMLとして解釈した | 描画先に応じた安全な出力。今回はtextContent |

証拠コードは領域・リセットごとに変わります。この資料の固定文字列で代用せず、その場のレスポンスから取得してください。XSSの成功通知は教育用のブラウザ報告であり、不正申告を完全に防ぐ採点機構ではありません。
